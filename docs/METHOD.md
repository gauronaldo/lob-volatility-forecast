# Method

This is the research protocol of the project. It was written before any model
was fitted or scored, and the code implements it. Where the implementation
differs, the difference and its reason are listed in
[DEVIATIONS.md](DEVIATIONS.md). Section numbers are cited in the source code.

## 1. Research questions

Forecast the next 10 minutes of realized volatility (RV) for 112 anonymised
stocks from 10 minutes of limit-order-book and trade data, using the Kaggle
"Optiver Realized Volatility Prediction" dataset.

The goal is not a leaderboard score. The goal is to measure how much of the
reported accuracy survives when a model may only use information available at
forecast time.

- **RQ1.** Which microstructure features add value over naive persistence?
- **RQ2.** How does RMSPE change across validation schemes (random rows,
  grouped by time_id, blocked in time, walk-forward)?
- **RQ3.** How much of the gain from nearest-neighbour time_id features is
  look-ahead, i.e. comes from neighbours in the future?
- **RQ4.** Does a neural network add anything over gradient boosting, and at
  what training cost?

## 2. Protocol rules

1. **No look-ahead in the strict setting.** A feature for time_id `t` may use
   only: (a) the 600 s feature window of any stock at `t`; (b) feature windows
   and realized targets of time_ids strictly earlier than `t` in the recovered
   order; (c) statistics fitted on the training rows of the current split.
2. **The holdout is opened once.** Holdout targets are not read, scored or
   plotted before stage S8. Until the holdout is cut in S4, every target is
   treated as a holdout target: no target statistic, no metric, no model fit.
   The single exception is the direction check of 5.1 step 4, restricted as
   described there. Feature windows of holdout time_ids may be read at any
   stage; order recovery needs them.
3. **Fit on train, apply to validation.** Scalers, quantile transforms,
   per-stock statistics, clusters, the residual variance used in
   back-transforms, and hyperparameters are fitted on training rows only.
4. **One split definition for all models.** Folds are generated once by
   `lobvol/cv.py`, saved, and loaded by every model.
5. **No competition data or credentials in git.**
6. **Every number ships with its context:** split scheme, setting, feature
   set, number of rows, seeds, and the naive baseline on the same rows.
7. **Negative results are reported as they are.** No tuning, re-splitting or
   re-seeding to make a result look better; every configuration tried is
   logged in `results/trials.json`.
8. **Frozen parameters (section 6) do not change after results are seen.**

## 3. Pipeline and gates

| Stage | Output | Gate (stop if it fails) |
| --- | --- | --- |
| S1 Data audit | `results/audit.md` | schema matches section 4 |
| S2 In-bucket features | `data/features/bucket.parquet` | feature tests pass (section 7, test 1) |
| S3 Time order | `time_order.parquet`, `results/order_validation.md` | every check in 5.1 passes, else fallback |
| S4 Splits, holdout cut | split files; target distribution of the development rows | split tests pass |
| S5 Sanity anchors, leakage ladder | naive and sanity-model scores, figure 1 | on development rows: naive RMSPE within 0.33-0.35; LightGBM, feature set A, `group_time`, RMSPE below 0.24 |
| S6 Fitted and temporal features | feature sets B, C_strict, C_comp, D and the gap variants; figure 2 | leakage tests pass |
| S7 Model ladder, tuning | out-of-fold predictions for every model | all models share the same folds |
| S8 Holdout | `results/holdout/` | runs exactly once, after all models are frozen |
| S9 Report | README, `reports/report.md`, 5 figures | every number regenerated by the CLI |

The S5 thresholds are sanity anchors taken from public repositories (naive
about 0.341; a 33-feature LightGBM with GroupKFold about 0.226). They are
self-reported and were measured on all rows; here they are checked on
development rows only. A large deviation most likely means a bug.

S1 records size on disk, rows per file, missing (stock, time_id) pairs, the
share of buckets whose first row is at second 0, buckets without trades,
duplicate rows, dtypes and the least liquid stocks. S1 does not look at
`target`; its distribution is recorded in S4, on development rows only.

## 4. Data and definitions

Raw files:

- `book_train.parquet/stock_id=<n>/`: `time_id, seconds_in_bucket,
  bid_price1, ask_price1, bid_price2, ask_price2, bid_size1, ask_size1,
  bid_size2, ask_size2`. A row exists only for seconds in which the book
  changed. Prices are normalised within each (stock_id, time_id).
- `trade_train.parquet/stock_id=<n>/`: `time_id, seconds_in_bucket, price,
  size, order_count`. Sparse; some buckets have no trades.
- `train.csv`: `stock_id, time_id, target`; at most 112 x 3,830 rows.
- The competition test files are small samples and are not used.

`time_id` values are shuffled, but one `time_id` denotes the same real
interval for all stocks. The target is the RV of the 10 minutes that follow
the feature window; the two windows do not overlap.

```
WAP1_t = (bid_price1*ask_size1 + ask_price1*bid_size1) / (bid_size1 + ask_size1)
WAP2_t = the same with level-2 prices and sizes
r_t    = log(WAP_t) - log(WAP_{t-1})        within one bucket only
RV     = sqrt( sum_t r_t^2 )
RMSPE  = sqrt( mean_i ((y_i - yhat_i) / y_i)^2 )
```

**Grid.** Each bucket is forward-filled onto a 1-second grid from its first
observed second to second 599. Forward-filling adds only zero returns, so RV
is unchanged, while averages of spread, depth and imbalance become
time-weighted. Nothing is filled across buckets or back-filled.

**Loss alignment** (derived in `lobvol/evaluation.py`):

- Minimising RMSPE is weighted least squares with weights `1/y^2`.
- With the ratio target `q = y / x`, where `x` is the current RV, the
  percentage error of `y` equals the percentage error of `q`, so the weights
  are `1/q^2`.
- If `log y` is modelled with mean `mu` and residual variance `s^2`, the
  RMSPE-optimal point forecast is `exp(mu - 1.5*s^2)`, not `exp(mu)`, with
  `s^2` estimated on training rows.

## 5. Method

### 5.1 Time-order recovery (S3)

1. **Price level.** For each (stock, time_id), the smallest positive gap
   between distinct normalised price levels equals `tick / P0`, so
   `P0 = 0.01 / min_gap` for a tick of 0.01. If only multi-tick gaps were
   observed, `P0` is too small by an integer factor; such outliers are set to
   NaN.
2. **Price matrices.** Rows = time_id, columns = stock: log real price at the
   start and at the end of the feature window.
3. **Ordering.** Embed the time_ids in one dimension. Candidates are compared
   on synthetic data with a known order (test 6).
4. **Direction.** A 1-D embedding has no sign. It is decided from prices: in
   the true direction the mean distance from `end(i)` to `start(i+1)` is
   smaller than from `end(i+1)` to `start(i)`. One check uses targets for this
   single sign: `corr(log target_i, log RV_{i+1})` should exceed
   `corr(log RV_i, log target_{i+1})`, because the target window of `i` lies
   between the two feature windows. It is computed on the first 80% of
   time_ids only, so that the targets of the future holdout are not read. Both
   cues must agree.
5. **Validation** (`results/order_validation.md`):
   - synthetic data with a known order: Spearman rho >= 0.99 and a 99th
     percentile of absolute rank displacement of at most the embargo `g`
     (rho alone allows a displacement of about 150 positions at 3,830
     time_ids);
   - real data: the median cross-sectional absolute log-price jump between
     consecutive time_ids is at most 0.25 times that of random pairs, with a
     permutation p-value below 0.01 (1,000 permutations);
   - real data: the lag-1 autocorrelation of market log-RV along the
     recovered order lies above the 99th percentile of shuffled orders;
   - real data, reported only (there is no ground truth): rank displacement
     between ordering methods.
6. **Fallback** if a check fails: `group_time` becomes the primary scheme,
   the holdout is a random 20% of time_ids, and RQ3 and lag features are
   dropped. (Not needed: every check passed.)

The recovered order is an estimate. Local swaps are expected, which is why
every temporal split uses an embargo. Lag and neighbour features have no
embargo, so the strict setting is strict only relative to the estimated
order; the gap variants of 5.3 measure how much that matters.

### 5.2 Splits (S4)

- **Holdout:** the last 20% of time_ids in recovered order, separated from
  the development set by an embargo of `g` time_ids, cut before any model is
  fitted or scored.
- **Schemes** on the development set:
  1. `kfold_rows`: shuffled 5-fold over rows;
  2. `group_time`: GroupKFold by time_id;
  3. `blocked_time`: 5 contiguous blocks, embargo `g` on both sides of the
     validation block;
  4. `walk_forward` (primary): 6 contiguous blocks; fold `i` trains on blocks
     `1..i` minus their last `g` time_ids and validates on block `i+1`.
- **Leakage ladder (figure 1, RQ2):** one LightGBM with fixed
  hyperparameters and trees, feature set A, scored under all four schemes.
  Scheme 2 vs 1 isolates same-interval leakage; 3 vs 2 temporal proximity;
  4 vs 3 also reflects smaller training sets and drift, so it is not pure
  leakage.

### 5.3 Features

In-bucket features (S2), per (stock, time_id), with no fitted statistics:

| Group | Contents |
| --- | --- |
| Realized | RV of WAP1, WAP2 and trade price; realized quarticity; upside and downside semivariance |
| Multi-window | the same on the last 300 s and 150 s; RV per minute; second-half over first-half ratio |
| Book | relative spread (mean, std), level-1 and level-2 size imbalance, total depth, abs(WAP1 - WAP2), number of book updates |
| Trades | seconds with trades, volume, order count, trade-price RV, a no-trade indicator |

Cross-sectional and temporal features:

| Group | Contents | Condition |
| --- | --- | --- |
| Same-time market | leave-one-out mean and std of RV over the other stocks at the same time_id; own RV over market RV | feature windows only |
| Stock level | typical RV, spread and update count of the stock | training rows of the split |
| Stock clusters | KMeans on the stock-by-stock correlation of log RV; cluster mean RV at the same time_id | fitted on training rows |
| Neighbours `NN[S]` | mean of own RV and market RV over the `k` nearest time_ids, in price space and in volatility space | candidates `S` = PAST or ANY; feature windows only |
| Lags `LAG` | RV and realized target of the previous time_id; mean over the previous 6 | strictly earlier time_ids |

Feature sets:

- **A** = in-bucket + same-time market
- **B** = A + stock level + stock clusters
- **C_strict** = B + `NN[PAST]`
- **C_comp** = B + `NN[ANY]` (competition setting; look-ahead by design)
- **D** = C_strict + `LAG` (the best honest model)

RQ3 is answered by RMSPE(C_strict) - RMSPE(C_comp) under `walk_forward`,
with a paired interval, and confirmed on the holdout. Both sets share
hyperparameters and feature list apart from the candidate set.

**Order-error sensitivity.** `C_strict_gap` and `D_gap` require every
neighbour and lag candidate of `t` to lie at least `g` positions earlier
(lag 1 becomes lag `g`). If the gain over B disappears with the gap, the
strict result depends on the local order being right.

**Feature selection.** Three seeded Gaussian noise columns are added; a
feature is dropped if its importance falls below the best noise column. It is
run on the training rows of each fold and cached per (feature set, scheme,
fold). C_comp reuses the list of C_strict with each `NN[PAST]` feature
replaced by its `NN[ANY]` counterpart.

### 5.4 Models (S7)

All models use the same folds, output `y` on the original scale and are
scored by RMSPE.

1. **naive:** `yhat = RV_600`.
2. **har_ridge:** Ridge on `log y` with `log RV_600`, `log RV_300`,
   `log RV_150`, log market RV and stock fixed effects (Corsi's HAR-RV adapted
   to one bucket). Back-transform `exp(mu - 1.5*s^2)`.
3. **forest:** RandomForestRegressor on the ratio target with weights `1/q^2`.
4. **gbdt:** LightGBM on the ratio target with weights `1/q^2` and
   `stock_id` as a categorical feature. Optuna TPE, 40 trials, tuned once on
   feature set B with seed 0 (B is the common base of C_strict, C_comp and D,
   so tuning favours neither side of RQ3), then fixed everywhere. Early
   stopping on an inner split (the last 15% of training time_ids), never on
   the validation fold.
5. **mlp** (PyTorch): quantile-normalised inputs, a stock embedding, target
   `log q`, loss = mean squared percentage error of `y`, early stopping on
   the inner split. Not tuned.
6. **blend:** non-negative weights summing to 1, fitted on out-of-fold
   predictions only.

Ratio denominator `x = max(RV_600, floor)`, with `floor` the 1st percentile
of positive `RV_600` in the training rows. `gbdt` and `mlp` average 3 seeds.

The development RMSPE of a tuned model is optimistic, because the tuning
objective is the reported metric; tables mark it. On the development set,
claims rest on paired differences between feature sets that share
hyperparameters; for the level of a model, on the holdout.

### 5.5 Evaluation

- Pooled RMSPE per fold; mean and standard deviation over folds.
- **Uncertainty:** paired moving-block bootstrap over consecutive time_ids,
  keeping all stocks of a time_id together; 1,000 resamples; 95% intervals.
- **Diebold-Mariano** on adjacent rungs, on the holdout: per-time_id mean
  squared percentage error, Newey-West variance, Harvey-Leybourne-Newbold
  correction.
- **Ablation:** refit `gbdt` with each feature group removed.
- **SHAP:** TreeSHAP, aggregated by feature group.
- **Error analysis:** by stock, by decile of market RV, by position in time;
  calibration; with and without the least liquid stock.

### 5.6 Holdout protocol (S8)

1. Freeze the code, the configs and the list of models and feature sets.
2. Refit each frozen model on the full development set. Fitted statistics
   come from the development set only. Strict features of holdout rows may
   use earlier holdout time_ids, including their realized targets, as a live
   forecaster could.
3. Predict the holdout once and write `results/holdout/`.
4. No modelling changes afterwards.

## 6. Frozen parameters

| Parameter | Value |
| --- | --- |
| Holdout fraction | 0.20 |
| Embargo `g` | 10 time_ids |
| Walk-forward folds | 5 |
| Windows | 600, 300, 150 s |
| Neighbours `k` | 5 and 20 |
| Lags | 1, and the mean of the last 6 |
| Inner split for early stopping | last 15% of training time_ids |
| Optuna trials | 40, run once, on feature set B, seed 0 |
| Order-error gap | `g` = 10 time_ids |
| Order checks | jump ratio <= 0.25; p < 0.01; autocorrelation above the 99th percentile; 1,000 permutations |
| Seeds | 0, 1, 2 |
| Bootstrap | 1,000 resamples, block length 20 time_ids |
| Tick size assumption | 0.01 |

## 7. Tests

All tests run on synthetic data from `lobvol.synth`; CI never needs Kaggle.

1. WAP, returns and RV match a hand-computed example; forward-filling leaves
   RV unchanged.
2. RMSPE matches a hand-computed example; weighted MSE with `1/q^2` on the
   ratio target equals squared RMSPE on `y`.
3. No split shares a time_id between training and validation; embargo gaps
   have the configured size; holdout time_ids appear in no development fold.
4. In the strict setting, every neighbour and lag index of `t` points to an
   earlier time_id; in the gap variants, at least `g` positions earlier.
5. Causality: for every validation time_id `t`, replacing the targets of all
   time_ids at or after `t` with random numbers leaves every strict feature
   of `t` bit-identical. For sets without `LAG`, replacing all validation
   targets leaves every validation feature bit-identical.
6. Order recovery returns Spearman rho >= 0.99, a 99th-percentile rank
   displacement of at most `g`, and the correct direction on synthetic data.
7. The back-transform `exp(mu - 1.5*s^2)` beats `exp(mu)` in RMSPE on
   simulated lognormal data.
